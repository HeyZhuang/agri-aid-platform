# 扶贫助农系统数据库设计

基于项目功能需求和代码分析，我为扶贫助农系统设计了完整的数据库结构。

## 核心功能模块

### 1. 系统管理员模块
- **登录认证**：admin表存储管理员信息
- **权限管理**：通过role字段控制权限
- **后台管理**：管理所有业务数据

### 2. 用户管理模块  
- **用户注册登录**：user表存储用户基本信息
- **账户余额**：account字段支持模拟充值功能
- **用户等级**：level字段区分用户类型

### 3. 扶贫政策模块
- **富文本编辑**：policy表的content字段存储富文本内容
- **评论功能**：comment表关联policy_id
- **点赞功能**：praise表实现真实点赞/取消点赞

### 4. 扶贫资讯模块
- **富文本编辑**：information表支持图片上传
- **浏览统计**：num字段记录浏览量

### 5. 农家乐模块
- **富文本介绍**：agritainment表存储详细信息
- **轮播图展示**：首页动态展示农家乐
- **评论系统**：支持用户留言评论

### 6. 扶贫商品模块
- **商品管理**：goods表存储商品详细信息
- **库存管理**：num字段控制库存，sales字段记录销量
- **分类管理**：category字段支持商品分类

### 7. 订单管理模块
- **下单流程**：orders表记录完整订单信息
- **发货管理**：支持快递公司和单号录入
- **状态跟踪**：从待发货到已完成的完整流程

### 8. 申请审核模块
- **贫困户申请**：poorapply表支持文件上传
- **项目申请**：projectapply表支持农家乐项目申请
- **审核流程**：待审核 → 审核通过/拒绝

## 数据库设计亮点

### 1. 点赞功能的巧妙设计
```sql
-- 点赞表设计
CREATE TABLE `praise` (
  `user_id` int(10) NOT NULL,
  `policy_id` int(10) NOT NULL,
  `status` tinyint(1) DEFAULT 1, -- 1-点赞，0-取消点赞
  UNIQUE KEY `uk_user_policy` (`user_id`, `policy_id`)
);
```
- 通过status字段实现真实的点赞/取消点赞
- 唯一约束确保一个用户对一个政策只能有一条记录
- 支持用户查看历史点赞记录

### 2. 多级评论系统
```sql
-- 评论表设计
CREATE TABLE `comment` (
  `parent_id` int(10) DEFAULT 0, -- 0表示一级评论
  `reply_to_user_id` int(10) DEFAULT NULL,
  `reply_to_user_name` varchar(255) DEFAULT NULL
);
```
- 支持无限级回复
- 记录回复目标用户信息
- 便于前端渲染评论树结构

### 3. 模拟充值闭环设计
```sql
-- 用户余额管理
CREATE TABLE `user` (
  `account` decimal(10,2) DEFAULT 0.00 -- 账户余额
);

-- 订单表关联
CREATE TABLE `orders` (
  `total_price` decimal(10,2) NOT NULL -- 订单总价
);
```
- 下单时检查余额是否充足
- 支付成功后扣除相应金额
- 实现完整的资金流转闭环

### 4. 富文本内容存储
```sql
-- 政策、资讯、农家乐均支持富文本
`content` longtext CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci
```
- 使用longtext类型存储富文本HTML
- 支持富文本内部图片上传
- utf8mb4字符集支持emoji等特殊字符

## 索引设计策略

### 主要索引
- **主键索引**：所有表的id字段
- **唯一索引**：用户名、订单号等唯一字段
- **业务索引**：user_id、status等常用查询字段

### 查询优化
```sql
-- 用户订单查询优化
INDEX `idx_user_id` (`user_id`)

-- 商品状态查询优化  
INDEX `idx_status` (`status`)

-- 点赞关联查询优化
INDEX `idx_policy_id` (`policy_id`)
```

## 数据完整性保证

### 1. 字段约束
- NOT NULL约束保证关键字段不为空
- DEFAULT值设置合理的默认状态
- 适当的字段长度限制

### 2. 唯一性约束
- 用户名、订单号等业务唯一字段
- 点赞表的用户-政策组合唯一性

### 3. 状态管理
- 使用枚举值管理订单状态、申请状态等
- 软删除机制保护重要数据
